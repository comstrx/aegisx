## What changed

- Captured requests reserve one whole-journey slot before forwarding. Required admission rejects new work with 503 when capacity/storage health cannot support it.
- Lifecycle phases move into a terminal batch; serialization is outside SQL transactions. Up to 32 ready batches commit together without a batching timer. Failures retain the bounded batch for retry.
- One shared FIFO write coordinator covers event, verdict and analysis-journal writers. Proxy cache lookups and WAL reads do not acquire this write gate.
- Defaults are `set_persistence { admission="required", synchronous="full" }` and `set_model { on_overload="reject" }`. Explicit best-effort/skip/NORMAL modes remain available.
- Model capacity is reserved before forwarding; inference still runs only after completion. A batch contains at most 32 jobs; normalization releases raw samples before inference.
- Normalized numeric jobs are committed before inference and results are group-committed afterward. On restart, compatible committed pending jobs are scored **for observation only**; recovery never replays restrictions, cancellations or webhooks.
- Indexed retention removes entire captured journeys. A new operator-revision check inside the serialized cancellation writer prevents stale model intent from overriding intervening human changes.
- Panel/API distinguish committed work, queue occupancy, pre-forward rejection, omissions, recovery, journal health and inference time.

Storage queue capacity now counts **journeys**, whereas v0.4 counted **events**. This changes the memory meaning of the same configured number. Active/queued capture is volatile; numeric recovery begins only after journal commit. FULL synchronization cannot preserve work that never reached a transaction commit. Backend event HTTP 202 is acceptance into bounded memory, not a durability acknowledgement.

## Forwarding comparison

[Final raw trials](2026-10-01-v05-final.json). Local WSL loopback; Python asyncio backend and load generator share the host; 128-byte HTTP/1.1 responses; persistent connections; 16 clients; two proxy workers; model off. Each of three alternating trials per binary/mode has 512 warmup plus 60,000 measured requests. Capture queue 65,536; retention 1,000,000. No build/training/browser/test job ran concurrently.

Median of three trials:

| Mode | v0.4 requests/s | v0.5 requests/s | v0.4 p95 | v0.5 p95 |
| --- | ---: | ---: | ---: | ---: |
| Proxy only | 28,869 | 29,158 | 0.879 ms | 0.882 ms |
| Full capture | 13,462 | 11,617 | 2.060 ms | 2.346 ms |

Proxy-only +1.0% is within host variability; no general speedup is established. The first baseline pure-proxy trial was unusually slow (13,199/s versus 28,869–29,977/s); it remains in the raw evidence.

Full-capture forwarding was **13.7% slower**, while doing substantially more durable work:

| Capture trial | v0.4 dropped events | v0.4 persisted terminal requests | v0.5 persisted terminal requests | v0.5 persisted events | v0.5 post-traffic drain |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 235,058 | 26,930 | 60,512 | 423,584 | 14.06 s |
| 2 | 221,479 | 28,920 | 60,512 | 423,584 | 23.65 s |
| 3 | 207,798 | 30,748 | 60,512 | 423,584 | 19.33 s |

Every current trial retained all expected seven-event journeys with zero omitted batches. A baseline terminal row alone does not prove its other phases survived. v0.5's legacy `dropped_events` field counts omitted journey batches; baseline counts individual events. Zero is comparable; nonzero counts are not the same unit.

**The forwarding rate excludes the later drain.** The large queue buffers a burst; 11,617/s is not sustained lossless SQLite capacity. FULL versus the older NORMAL synchronization and different queue units also make this unequal work, not an isolated CPU optimization comparison.

Earlier v0.5 measurements remain available: [initial forwarding](2026-10-01-v05.json), [initial pipeline](2026-10-01-v05-pipeline.json). They exposed repeated event copies and SQLite writer contention. After moving batches, sharing the writer gate and group-committing numeric jobs, the final pipeline below had no journal/storage write failures. Historical files were not overwritten.

## Actual model training and evaluation

Architecture `40 -> 384 -> 320 -> 128 -> 1`: **180,161 parameters**, feature schema 2, lifecycle-v4. One shared architecture JSON drives Python construction and Rust count validation.

31,986 deduplicated rows: 31,067 from HttpParamsDataset and 919 selected novel FuzzDB samples. Sources, commits, checksums and notices are pinned in [sources.json](../../model/sources.json). The loader quarantines conflicting exact labels and groups canonical templates plus identical normalized inputs across sources before splitting.

Actual local WSL CPU training: seed 42, batch 256, balanced loss, AdamW 0.001, gradient clipping, early stopping. Target 140 epochs; stopped at 57, best epoch 37; initial training approximately 58 seconds on one CPU thread. No cloud account, upload or paid run was used. Checkpoint resume/export subsequently finalized exact validation calibration.

- Train / validation / test: 21,864 / 5,707 / 4,415 rows.
- Threshold selected only on exported-ONNX validation scores: **0.02492976188659668**.
- Held-out test: TP 2,544; FN 3; FP 28; TN 1,840. Recall **99.88%**, benign false-positive rate **1.50%**. A 1% validation budget did not guarantee 1% test FPR.
- PyTorch/ONNX maximum absolute error: **1.19e-7**; Rust parity checks pass.
- Independent selected OWASP CRS positive fixtures: **2,420 / 2,822 = 85.75% recall**, compared with v0.4 **87.85%**. The larger model regressed on that check.
- A separate overlap audit removes 242 matches against the complete source corpus: 2,408 / 2,580 = 93.33%. This is a different subset, not a replacement headline or evidence of improvement over v0.4. Near-duplicates and fixture-context limitations remain.
- CRS contains only selected positives here; it gives no benign FPR estimate and was not used for training/calibration.

[Training report](../../model/weights/report.json), [external report](../../model/weights/external-report.json), [model documentation](../../model/README.md). Public payload sources do not contain real actor histories, backend outcomes or runtime labels; unsupported input weights remain zero. Dictionary membership is context-dependent, not proof of a real attack.

The artifact remains `deployment_ready=false`, with the sample configuration in **observe**. Its default server threshold 0.95 differs from the calibrated research threshold; the reported metrics do not describe 0.95. More parameters are not evidence of greater field accuracy.

## Reproduction

From the workspace root:

```sh
python3 scripts/build.py
cd server
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
AEGISX_BIN=/var/www/tools/aegisx/dist/aegisx python3 -m unittest discover -s tests -p '*.py' -v
python3 tests/benchmark.py --baseline ../tmp/aegisx-v0.4-baseline --current ../dist/aegisx --requests 60000 --output benchmarks/reproduction.json
python3 tests/pipeline_benchmark.py --output benchmarks/pipeline-reproduction.json
cd ../model
uv run --locked pytest -q
uv run --locked ruff check .
uv run --locked aegisx-model train-http --data data/sources/payload_full.csv --extra data/fuzzdb --output weights --epochs 140 --learning-rate 0.001 --batch-size 256 --balance --patience 20
```

Use the pinned source fetch instructions in model/README.md first if data is absent. Benchmarks should run without training/build/browser contention. Training rewrites model artifacts; rebuild the executable afterward.

## Remaining limits

Crash recovery does not reconstruct uncommitted HTTP journeys. Rolling behavioral memory is volatile. Webhook delivery has no durable outbox, although cancellation intents are durable and pollable. ACME, DNS discovery, verified HTTP/2–3, WebSocket/CONNECT, Kubernetes integration, total connection-flood protection and production field evaluation remain outside the implemented subset.

Local evidence above establishes specific behavior under the measured scenarios; it is not a universal security, durability or throughput guarantee.
