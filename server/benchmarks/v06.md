# AegisX 0.6 — measured release evidence

Verified locally on 2026-10-01. This release expands the model, reduces forwarding overhead and replaces the dashboard. **The requested 50,000 forwarded requests/s target has not been reached.** More parameters and a redesigned UI do not establish production security or Nginx/Caddy parity.

## Delivered artifact

- GNU Linux x86-64 executable: `dist/aegisx`, **44,196,008 bytes**.
- SHA256: `06c32d988a39903222f954ac0ab14c081b8cea8d222e8971a3339c32143de231`.
- Embedded static Next.js panel, model, ONNX CPU runtime, Lua, SQLite and OpenSSL. Standard Linux C/C++ shared libraries remain required; no production Node/Python/Redis service.
- `dist/manifest.json` records exact model provenance and artifact identity. Dataset and allocator notices accompany it.

## Forwarding: paired, alternating measurements

[Raw final trials](2026-10-01-v06-final-native.json). Intel i5-10210U, four physical/eight logical CPUs, shared WSL2 host; wrk and a native epoll backend run on that same machine. Eight proxy workers, two client threads, 128 keepalive connections, 128-byte HTTP/1.1 responses. Three 15-second trials per version with alternating order and warmup. No training, build or browser QA ran concurrently; unrelated user services remained running.

Capture, model, decisions and response cache are disabled. **Every measured request is forwarded**; rejected requests/cache hits are not counted as forwarding capacity. The runner fails on socket errors or non-2xx results.

| Version | Trial 1 req/s | Trial 2 req/s | Trial 3 req/s | Median req/s |
| --- | ---: | ---: | ---: | ---: |
| Preserved v0.5 | 24,506.72 | 26,226.02 | 16,086.09 | 24,506.72 |
| Final v0.6 | 27,271.53 | 32,022.20 | 27,126.48 | **27,271.53** |

The median improved **11.28% in this run**, with substantial shared-host variance. Best observed final trial: **32,022.20/s**, not 50,000/s. The direct backend measured 214,718.79/s, so the backend alone is not the observed ceiling. This is neither a hardware-independent speedup nor sustained production capacity.

The memory cost is material: baseline RSS 45.6–46.8 MB; current RSS **75.5–76.8 MB**. Current proxy CPU averaged 4.68–5.38 logical cores. Tail latency did not uniformly improve: current p99 18.98–28.02 ms versus baseline 11.02–29.11 ms. Throughput alone does not establish better latency.

### Changes supported by inspection and measurement

- Immutable route candidate index supports up to 1,024 routes while preserving host/path/method/header priority. No full route scan for unrelated prefixes.
- Canonical paths are validated once, backend authority values compiled once, retry storage is fixed-size, and multi-backend selection avoids a candidate vector.
- UUID v4 uses the existing uuid crate's `fast-rng` CSPRNG path, avoiding per-request OS entropy calls.
- In default non-work-stealing mode, each worker has its own single-thread Pingora runtime, connector and upstream reuse pool. Linux SO_REUSEPORT distributes accepts. Shared Services still owns global admission, caches, storage, inference and policy once.
- Lua exposes `work_stealing`, `accept_tasks` and `upstream_keepalive_capacity`; these are restart-required controls. Work-stealing mode remains available.
- Default allocator is mimalloc 0.1.52 with `secure` enabled (native 3.3.2); `--no-default-features` retains the system allocator. This does not remove Rust's allocation budgets or make the program memory-safe by assertion.
- Content extraction uses in-place shrinking decode and memchr-backed searches; schema dimensions are generated from shared JSON.

[Allocator-only comparison](2026-10-01-v06-allocator-comparison.json) preceded the final connector change: median 22,640.92/s system allocator versus 25,376.37/s secure mimalloc, with higher RSS and wide variance. [Final worker-isolation probe](2026-10-01-v06-isolated-workers-probe.json) reached 29,309.57/s. These are different artifacts/runs; their percentages must not be added together.

A 16 KiB write-buffer experiment was slower than the existing unbuffered setting; it was not adopted as a new default. No custom unsafe SIMD/arena layer or dependency-source patch was introduced. memchr dispatches its supported optimized search implementation. Further work needs isolated-host profiling and representative multi-route/TLS/capture workloads, not a claim that the maximum possible speed has been attained.

## Model: larger context, actual training, measured compression

Architecture **104 → 640 → 512 → 256 → 1**, **526,977 parameters**, feature schema **3**. Sixty-four hashed byte-bigram/trigram features extend the earlier 40-input contract. Actual public-source training uses 31,067 HttpParams examples, 919 FuzzDB examples and 22,281 publisher-benign WCP examples. Class-independent URI/JSON envelopes produce **118,239 deduplicated rows**, not that many independent observations.

Connected groups keep capture sessions, parent augmentations, canonical templates and identical normalized vectors in one partition. Split sizes are 83,185/17,253/17,801. CPU training stopped at epoch 32, selecting epoch 8; source preparation, training and export took 326 seconds. Unsupported actor/history/outcome inputs remain zero-weighted rather than pretending that independent HTTP payloads contain runtime behavior.

Selected dynamic UINT8 artifact:
- **541,033 bytes**, down **74.50%** from 2,121,686-byte FP32.
- Verified SHA256: `4d8ce1f10dc4eb6479f8d376cbceb4c74e9415ba4a599cbf0c070cd487f9b432`.
- [Controlled follow-up timing](../../model/weights/runtime-benchmark.json): FP32 **71.168 µs**, UINT8 **44.485 µs**, medians of five alternating trials of 1,000 single-row CPU calls, 100 warmups and one ORT intra/inter thread. Repeats saved vectors, includes Python call overhead, excludes extraction/queue/disk/network; approximately **37.5% less inference time** on this host. This is separate from the noisier training-time promotion timings retained in metadata.
- Validation recalibrates the compressed artifact to threshold **0.16929742693901062**. Maximum validation score change was 0.1754; quantization is not numerically identical to FP32.

| Quality measure | Previous 180k model | New 527k UINT8 model |
| --- | ---: | ---: |
| Excluded WCP benign captures, 7,491 requests: FPR | 78.81% | **3.34%** |
| Selected OWASP CRS positive fixtures, 2,822 requests: recall | **85.75%** | 49.68% |
| New internal grouped test recall | Different training/test corpus | 99.638% |
| New internal grouped test FPR | Different training/test corpus | 0.725% |

The reduction in benign false alarms comes with a **large external attack-recall regression**. Each artifact uses its own validation threshold, not an equal-FPR operating point. The external diagnostics were inspected during development and motivated augmentation; they are not pristine acceptance sets, though their examples were never trained on or used for numeric threshold selection. Publisher labels and CRS rule expectations remain context-dependent.

`deployment_ready=false` remains explicit. The supplied server uses observe mode at a separate default threshold of 0.95. This model is not a proven fraud detector, upload scanner or learned load-balancer controller. Real independently labeled runtime behavior and fresh application/campaign holdouts are still needed.

## Panel and configuration

Six views: overview, requests, decisions, upstreams, analysis and effective configuration. The new local UI has light/dark themes, a consistent teal/navy identity, responsive navigation, live SVG charts, paginated request tables, search/filter, actual journey/operation details and authenticated action forms. Loading/empty/stale/error states, inline errors, toasts, confirmation, focus handling, keyboard shortcuts and reduced-motion support are included.

Polling is abortable every second, with pause/resume and explicit refresh after actions. Tokens remain in tab memory. Effective configuration is a safe read-only projection, not raw Lua or secrets. Charts contain measured counters, not fabricated traffic. Backend-internal visibility still requires instrumentation.

## Cache, analysis and journal coverage

[Pipeline trials](2026-10-01-v06-pipeline.json) use eight Python clients, fresh downstream connections, 3,000 requests per trial, a shared Python backend, summary capture, FULL SQLite synchronization and a 64-job analysis reservation budget. This is a different workload from the native pure-proxy benchmark.

Warm decision-cache trials made 5–8 database reads per 3,000 requests; distinct-actor cold trials made 3,000 reads. Warm/cold throughput is client/workload limited here and does not prove a cache speedup.

Across three background trials, **4,700 requests were forwarded and all 4,700 finished analysis**; **4,300 returned pre-forward 503** because the bounded analysis budget filled. All 9,000 journey summaries / 27,000 events committed, with no reported omitted batches, stale jobs, inference errors, journal errors or SQL retries. Accepted forwarding throughput was 2,361 / 1,439 / 1,414 requests/s. These are not 50k/s full-observability results; pressure rejection is an availability cost, not extra successful throughput.

Mean normalization plus ORT time was 54.6–60.4 microseconds per accepted tiny request. Journal/fsync, queueing and networking are additional costs. No assertion is made that these short trials prove sustained or crash-durable unlimited ingestion.

## Safety and remaining boundaries

Post-completion inference is preserved. Late AI/operator decisions affect future admissions; no late transport kill switch. Cooperative cancellation requires explicit backend support. SQLite decisions remain authoritative, with commit-before-cache publication. Required capture and analysis overload can reject before forwarding rather than silently omit admitted work. Shared rate policy is tested across both worker topologies.

Active/uncommitted capture, pre-journal jobs and queued webhook delivery still have crash windows. Finite queues and hardware cannot provide unlimited capacity. Broader HTTP/2/3, WebSocket/CONNECT, ACME/DNS, Kubernetes, automatic OpenTelemetry, durable webhook outbox and comprehensive production security validation remain outside the verified implementation. No enterprise/Grafana/Nginx/Caddy equivalence is claimed.
