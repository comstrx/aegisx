## Detection quality and limitations

At a **0.1% empirical validation FPR budget**, held-out content recall rises from **81.22% to 98.39%** (1,771/1,800 positives). Both models have zero observed false positives among 975 benign internal test rows. Selected journey recall is **95.31%** (325/341), with 0/1,083 observed false positives.

The old journey model cannot meet the validation FPR budget on the expanded transaction lab, even at threshold 1; its test result is not a matched-budget comparison. The supervised student's journey test is better than the selected distilled student's, but the validation-frozen selection was not changed after inspecting test results.

The transfer teacher obtains 99.2% recall and 1/750 false positives on its balanced 1,500-row content test. Only its head was newly trained; the pretrained encoder was frozen. The teacher sees a request prefix, not the complete lifecycle.

**External detection is still weak.** At the strict validation operating point, previously inspected CRS diagnostics improve from 4.85% to **9.25% recall**, while WCP benign false positives increase from 3/7,491 to **7/7,491 (0.093%)**. At the 1% validation operating point, recall improves from 16.12% to **26.26%**, with benign FPR increasing from 0.561% to **0.748%**. These development diagnostics are not pristine acceptance sets or verified exploit outcomes.

At an unchanged scalar threshold 0.95, the new artifact instead has lower external FPR **and lower recall** than the old artifact. Scores from different models are not interchangeable calibrations. The model remains `deployment_ready=false`, research/observe only. Zero observed errors on a small fixture is not a zero-error guarantee.

Lua can set `content_threshold` and `journey_threshold` independently. Recommended strict values are 0.9491480588912964 and 0.9946383237838745. A route's explicit scalar threshold overrides both. Artifact recommendations never silently override Lua, whose scalar default remains 0.95.

## Rust behavior and integrity

- SQLite remains authoritative. Concurrent queued misses for the same decision are rechecked in the repository worker; a deterministic 100-reader test performs one SQL read and 99 coalesced reads.
- Cached verdicts share `Arc` values instead of cloning their strings. Prepared SQLite statements are reused. Writes publish cache entries only after commit; a forced failed commit preserves the previous cache value.
- Stored decisions must agree with their row key and expiry, contain bounded valid identifiers and fit a byte limit. Corrupt records surface through the configured lookup-failure policy, rather than becoming a fabricated allow or block. The persisted identity secret must have the expected length.
- Rolling totals avoid scanning all time buckets for each request in the same second. Time-window advancement and latest-completion latency remain correct under out-of-order lock acquisition.
- Normalization avoids unnecessary allocations and reuses n-gram hash prefixes. Complete-input hashing uses stack chunks without changing its byte sequence; parity and key separation remain checked.
- Pure forwarding, with capture/model/rate/decision features disabled, returns before constructing the repository lookup path.
- Missing modalities cannot trigger a head just because its threshold is zero. Finite input/output checks and `risk=max(content,journey)` are enforced.

Inference remains **post-completion**. New verdicts govern later admissions, never abort an already-forwarded request. Numeric history is bounded RAM state and resets on restart; committed decisions persist. Raw text is transient, so an interrupted text-analysis job cannot be reconstructed from the numeric journal.

Final [forwarding report](2026-10-02-v09-final-forwarding.json) and [policy report](2026-10-02-v09-final-policy.json): three alternating trials per executable, 15s forwarding/10s policy, 2 proxy workers pinned to logical CPUs 0,2, 2 native epoll backend workers on 4,5 and 2 wrk threads on 6,7. Final policy CPU consumption varies from 1.69 to 1.98 cores; baseline ranges from 1.20 to 1.97. Large trial variation and earlier opposite results prevent attributing a stable gain or loss to an individual optimization. The adverse observation is retained; **general proxy acceleration has not been established**.

Earlier measurements are retained: [unpinned forwarding](2026-10-02-v09-forwarding.json) showed a 13.4% regression, [pinned forwarding](2026-10-02-v09-forwarding-pinned.json) a 3.4% regression, and [unpinned policy](2026-10-02-v09-policy.json) a 4.5% improvement for the intermediate candidate. Its hash is different from the final executable. No sustained 30–40k/s or 50k/s claim is made. Final proxy-only RSS is 49.79–50.65MB; policy RSS is 52.14–54.65MB, so universal memory reduction is not demonstrated either.

[Final complete-pipeline trials](2026-10-02-v09-final-pipeline.json) use eight clients, 3,000 requests per trial, fresh connections, a shared Python client/backend, and three trials for each of warm decisions, cold decisions and background analysis. In each warm trial, 3,000 requests require only one SQL decision read; queued simultaneous misses account for 3–7 coalesced reads. Cold trials use 3,000 distinct actors and 3,000 SQL reads. All requests complete with 200 and no decision read/write errors.

Background mode captures request text and summary events, uses SQLite FULL and the numeric journal, 64 analysis slots and a bounded 256-slot waiting room with a 1,000ms deadline. No response text or backend instrumentation is included in this throughput fixture; separate functional tests cover those inputs.

- All **9,000 background requests were forwarded, analyzed and persisted**, with no reported analysis drop, expiry, failure, storage drop or HTTP rejection.
- Throughput 615.9 / 497.0 / 626.8 requests/s; median **615.9/s**.
- p95 HTTP latency ranges **41.1–74.1ms** under worker backpressure.
- A separately run [v0.8 baseline](2026-10-02-v09-pipeline-baseline.json) has median **328.7/s** with the same fixture. Host/time variation prevents treating this unpaired difference as an isolated causal speedup. The paired model-only benchmark above gives cleaner evidence for lower inference cost.

The waiting queue absorbs finite bursts; it does not make sustained overload lossless, durable or latency-free. This is a local fixture result, not a service-capacity certification.
