## Forwarding comparison

[Final raw trials](2026-10-01-v04-final.json) compare the preserved v0.3 binary against the final v0.4 binary. Same WSL host, Python asyncio client/backend, 128-byte HTTP/1.1 bodies, persistent connections, 16 clients, 512 warmup requests and 60,000 measured requests per trial. Three alternating-order trials per binary/mode; two Rust proxy threads. No project build/training/browser test ran during this comparison. Host activity/frequency are not controlled.

Medians:

| Mode | v0.3 requests/s | v0.4 requests/s | v0.3 p95 | v0.4 p95 |
| --- | ---: | ---: | ---: | ---: |
| Proxy only | 31,231 | 31,610 | 0.691 ms | 0.659 ms |
| Full unsampled capture | 12,921 | 15,703 | 1.915 ms | 1.591 ms |

Pure forwarding differs by +1.2%, within observed host variability. This supports broadly comparable local performance, not a universal speedup or an NGINX/Caddy comparison.

Full capture has different recorded fields and severe drop pressure. Its forwarding throughput is **not** lossless recording capacity. Dropped events (including warmup):

| Version | Trial 1 | Trial 2 | Trial 3 |
| --- | ---: | ---: | ---: |
| v0.3 | 233,581 | 216,165 | 215,755 |
| v0.4 | 226,108 | 216,987 | 290,012 |

Explicit summary/sampling reduces work but changes coverage. Capture queues are bounded, best effort; they cannot be described as production lossless telemetry.

## What changed after the initial measurement

[Initial raw comparison](2026-10-01-v04.json) is preserved. Initial v0.4 pure-forward median was 26,927/s versus 28,754/s for v0.3. The first baseline trial was unusually slow in both runs; all trials remain visible.

Inspection found unused live-counter/histogram/Arc-ticket updates when control was disabled. v0.4 now skips those updates while retaining independent SQLite sampling. Decision policy fingerprints are also precomputed per route rather than formatting the full policy per request. The final run restores comparable forwarding performance; machine variability prevents attributing every difference to this change.

## Cache-aside and asynchronous analysis

[Pipeline raw trials](2026-10-01-v04-pipeline.json) use eight clients and 3,000 requests per trial, with fresh downstream connections. They are separate from the persistent-connection forwarding test. Cache-only trials disable model/capture; cold trials use distinct trusted test actors.

Warm repeated actors triggered only 5–8 database reads per 3,000 requests; subsequent reads used the negative cache. Cold actors triggered exactly 3,000 repository reads per trial. Concurrent initial misses are not coalesced. This proves read-path behavior; the shared-host timings do not establish an isolated SQLite latency or a general cache speed multiplier.

Three short background trials completed 9,000/9,000 analysis jobs, with no skipped/expired/failed analysis and no observed dropped-event counter increments at measurement time. Summary capture was enabled, with a 64-job model queue and 65,536-event storage queue.

Mean content extraction + normalization + ONNX time per trial: 0.0415 ms, 0.0492 ms, 0.0428 ms. These tiny requests have no uploaded bodies. This timing excludes queue wait, database commit and network traversal; it does not predict worst-case 64KiB samples or saturated sustained workloads.
