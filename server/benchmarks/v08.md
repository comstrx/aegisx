## Background pipeline and finite capacity

[Three trials](2026-10-02-v08-pipeline.json): eight clients,3,000 requests each, fresh downstream connections, request-text analysis, summary capture, SQLite FULL and numeric journal,64 analysis slots,256 waiting slots with1,000ms deadline. No response text or backend instrumentation in this throughput fixture; functional tests separately verify those inputs. The client/backend share this WSL host.

- All **9,000 requests forwarded, analyzed and persisted**; no reported analysis drops/expiry/failure, storage drops/retries or HTTP rejection.
- Forwarded throughput407.8 /379.1 /385.2 requests/s, median **385.2/s**.
- p50 HTTP latency1.58–1.78ms; p95 **77.9–87.4ms** under worker backpressure.
- 727–730 waiting episodes per trial; no full/timeout outcome.

The queue absorbs bounded bursts; it cannot make sustained arrival rates above worker capacity disappear. Increasing queue size adds memory/latency and eventual expiry risk. This is a local finite-load observation, not unlimited acceptance or crash durability.

## Intentional limits

1024 bytes per text stream,32 backend events and64 event-name bytes are model limits, not full-body/arbitrary-code visibility. Backend instrumentation is required. Response sampling is explicit opt-in and transient. Committed numeric jobs cannot reconstruct text after a crash, so recovery marks them unavailable rather than fabricating a verdict. Late results never interrupt an already-forwarded request. The controlled lab covers two narrow application behaviors; broader independent data and evaluation remain necessary.
