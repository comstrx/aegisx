### Implemented reductions

- Empty route tables take the fallback directly; header names/values and identity removal names are compiled at configuration time.
- Request-ID header values are constructed once and reused. Route header overrides are case-insensitive; ambiguous case-duplicate configuration names reject.
- Facts and path depth are built only when actor inspection needs them. Mandatory protocol, metadata and body limits remain.
- Unlimited single-backend admission uses one atomic increment instead of a conditional update; bounded admission retains its capacity check.
- Unused elapsed-clock reads are avoided. Inference borrows its normalized input instead of copying into a fresh vector.
- Upstream waits use registered notifications and the next passive cooldown expiry, replacing 25 ms polling per waiter.
- Secure mimalloc, immutable route indexing and worker-local Pingora connectors remain. No custom unsafe SIMD/arena or dependency-source patch was added.

A 4 KiB upstream write-buffer probe reached 32,437.09/s, but a real streaming test showed that known-length response chunks could be delayed until completion. **The default therefore remains unbuffered (0).** An explicitly configured buffer preserves complete body correctness but has this documented streaming tradeoff. Earlier probes remain in this directory; they are not final release measurements.

## Bounded waiting: measured acceptance

[Disabled](2026-10-02-v07-pipeline-false.json) and [enabled](2026-10-02-v07-pipeline-true.json) runs use the **same final binary**. Each mode has three 3,000-request trials with eight Python clients, fresh downstream connections and a Python backend on the shared host. Summary capture and numeric journal use FULL SQLite synchronization; analysis reservation capacity is 64. Enabled waiting uses 256 slots and a 1,000 ms deadline.

| Three-trial aggregate | Waiting disabled | Waiting enabled |
| --- | ---: | ---: |
| Requests attempted | 9,000 | 9,000 |
| Forwarded with HTTP 200 | 4,815 | **9,000** |
| Rejected before forwarding with 503 | 4,185 | **0** |
| Completed model analyses | 4,815 | **9,000** |
| Persisted journey summaries / events | 9,000 / 27,000 | **9,000 / 27,000** |
| Dropped batches / analysis failures / journal failures | 0 / 0 / 0 | 0 / 0 / 0 |

Enabled waiting resumed **1,330 wait episodes**, with no full/timeout/unavailable results. Accepted throughput by enabled trial was **1,164 / 1,728 / 1,037 req/s**; disabled was **1,555 / 871 / 941 req/s**. This is full background-pipeline work, not the pure-proxy benchmark.

Waiting absorbs bursts at a latency cost: enabled p95 was **17.46 / 6.01 / 37.57 ms**, versus disabled **4.40 / 3.20 / 2.04 ms** across all outcomes, including quick rejections. These are sequential closed-loop development trials, not an open-loop overload certification or unlimited acceptance guarantee.

### Queue contract

```lua
set_queue { capacity=256, timeout_ms=1000 }
```

Capacity bounds live wait episodes (0 disables; maximum 8,192); timeout is 1–30,000 ms. Both settings require restart. The supplied Lua enables waiting; the library default disables it.

Global in-flight capacity, upstream capacity/health and required storage/analysis reservations share one deadline per request, beginning at its first wait. Fast successful paths do not enter the waiting room. Release, health recovery or cooldown expiry resumes eligible work. Full/expired/unavailable capacity returns 503 before forwarding. There is no global FIFO fairness guarantee.

This keeps live HTTP connections waiting; it does not spool unbounded bodies, persist queued requests or replay writes. Cancellation drops wait permits; a disconnected peer is not actively polled while waiting, so release can wait for readiness/deadline. Committed bans are checked again after waiting and before preparing upstream headers. Late AI/operator decisions never kill an already-forwarded request.

Stats distinguish current waiting, capacity, entered/completed/resumed episodes, full, timeout, unavailable, cancelled and accumulated wait time. Multiple resources can produce multiple episodes for one request. Current queue state and completed mean wait are shown in the panel.

## Remaining boundaries and reproduction

Committed SQLite decisions remain authoritative with commit-before-cache publication. Active/uncommitted capture, pre-journal work and webhook delivery have crash windows. HTTP waiting is volatile and finite. General HTTP/2/3, WebSocket/CONNECT, ACME/DNS, Kubernetes controllers, durable webhook outbox, automatic OTel and production security validation remain outside verified scope. Backend job cancellation requires explicit cooperation; closing proxy I/O cannot undo application side effects.

```sh
python3 scripts/build.py
python3 server/tests/native_benchmark.py --binary tmp/aegisx-v0.6-baseline --binary dist/aegisx --proxy-threads 8 --connections 128 --trials 3 --seconds 15 --output server/benchmarks/local-128.json
python3 server/tests/native_benchmark.py --binary tmp/aegisx-v0.6-baseline --binary dist/aegisx --proxy-threads 8 --connections 256 --trials 3 --seconds 15 --output server/benchmarks/local-256.json
```

Baseline reproduction requires the matching preserved executable. Do not compare differently configured binaries or add percentages from different probes. Training reproduction is separately documented and requires a fresh authorized experiment ledger.
